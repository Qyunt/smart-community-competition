# 智慧社区工程：有什么、做到哪一步了

检查日期：2026-10-08。对象：你提供的 `【队名】-智慧社区复赛工程代码.zip`。

## 先理解这个项目

这是一个用 ROS 1 和 Gazebo 做的智慧社区机器人巡检仿真项目。Gazebo 提供社区场景和虚拟机器人，ROS 节点负责接收激光雷达、里程计和相机数据，控制机器人沿路线移动，在观察点抓图，并把识别结果送去输出或播报。

它已经有较完整的场景与巡检骨架，适合接着开发；完整的建图、导航、识别和比赛演示仍需要继续验收。源码文件存在、静态检查通过、在本机运行通过和识别准确率达标，是不同的完成程度。

## 当前正式场景

当前应使用文件名带 `4p2` 的 4.2×4.2 米场景。压缩包还保留早期 10×7.2 米版本，不能混用它的地图、坐标、机器人和路线。

当前场景静态检查识别到 50 个对象、27 个资产纹理、261 个连通道路逻辑格。包含 A/B/C/D 楼宇、两处红绿灯、人偶立牌、指示牌、垃圾桶、站房仪表、三处车牌、电动车和出发/返回区域等任务元素。

默认人物为 18 个独立立牌：16 个居民参考和 2 个外来人员参考，每个尺寸 150×50×5 毫米。当前工程将两街各放 9 人，这属于示例布置，不是识别程序得出的数量，也不是规则固定人数。电动车共 12 个：停车区 8 个正常、2 个倒伏，另有 2 个 A 街违停示例。

机器人为四麦克纳姆轮模型，外廓约 334×303×222 毫米。移动使用 Gazebo 平面运动插件近似全向运动，尚不是轮子与地面接触的真实动力学模型。传感器包含 360 度激光雷达、RGB/深度相机和单目任务相机，主要话题有 `/scan`、`/odom`、`/camera/*`、`/task_camera/image_raw`。

两处信号灯按红 10 秒、绿 15 秒、黄 3 秒切换，与本机规则 PDF 中的时序一致。

| 功能 | 已有内容 | 完成程度与限制 |
|---|---|---|
| 场景仿真 | world、纹理、机器人、传感器、动态红绿灯 | 已有成套资源；须以本机启动验收为准 |
| 路线设计 | 16 个任务点＋17 个过路点，共 33 个目标 | 已有固定测绘路线 |
| 沿路线巡检 | `sq_patrol_4p2.py`，使用里程计与 LiDAR，观察点存图 | 不是通过 move_base 规划路径的完整自主导航 |
| 红绿灯识别 | `sq_signal_vision_4p2.py`，从相机图像判断颜色，巡检等待红转绿 | 已有识别和等待逻辑，实际稳定性仍需测试 |
| 车牌 OCR | Python 3 EasyOCR 服务＋ROS 桥接节点 | 需要另建外部服务；旧说明仅记录已知三张图的冒烟测试 |
| 语音 | `sq_voice_4p2.py`，订阅结果并调用 `spd-say` | 需实际语音后端、中文支持和音频输出 |
| SLAM | GMapping 和建图巡检启动文件 | 有入口；不能仅靠文件判定全场建图完成 |
| 定位与导航 | AMCL、move_base、DWA 参数及 action 巡检节点 | 已有代码；33 点整圈实测尚需独立验收 |
| 视觉扩展 | `sq_vision_demo.py` 示例和巡检事件话题 | 没有随包 YOLO 权重；示例不能代替完成的检测模块 |

巡检观察事件 `/sq/patrol/observation` 携带任务 ID、任务类型、图像路径和时间，可作为以后接入人群、火灾、电动车等识别程序的统一入口。

## 哪些比赛任务还没有完成

16 个任务标签包括：两次红绿灯等待、A/B 街人群、指示牌、D 楼温度、A/B/C 楼火灾、垃圾桶、站房仪表、三辆车牌、电动车和返回泊车。当前多数任务的“完成”只表示到达观察位或保存图像，不能表示已经识别成功。

还需要补齐：人偶检测与街区计数、跨帧去重、外来人员框选与存图；指示牌识别并改变行驶决策；垃圾桶开闭和投放判断；火灾隐患计数；温度异常楼层定位；仪表读数；电动车违停和倒伏判断；停车位置与朝向验收。

## 需要特别留意的交接问题

1. 几何先验地图不是 SLAM 建出来的地图。某些文件虽然叫 `slam`，仍须核实生成流程、证据和后处理，不能按文件名判断。
2. 交接文档提到规则图道路表达和人群区曾有疑问，本包没有完整闭环证据，须拿规则图逐区核对。
3. 交接文档记录团队确认的比赛机器人为 400×400 毫米，而当前仿真仍是 334×303 毫米。这个 400 毫米参数来自交接记录，不能称为此次规则 PDF 中查到的尺寸。
4. 默认 OCR URL 是组员电脑的 `192.168.232.1:8765`，与你的 VMware 网段不同，不能直接使用。
5. 原安装脚本最后启动的是旧场景，并且有忽略依赖安装错误的行为。本次使用另行准备的部署脚本和当前场景入口。
6. 说明提到的 `docs/standee_review_20261002/` 目录没有出现在 ZIP 中；随包 `props_3d_review_20261002/` 的旧截图不能当作当前立牌现场验收图。
7. 旧视觉示例把 YOLO 放进 ROS Python 进程；Melodic 常用 Python 2，现代 YOLO 使用 Python 3，应参照 OCR 的桥接方式拆成独立 Python 3 服务。
