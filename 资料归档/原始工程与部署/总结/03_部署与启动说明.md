## 最简单的启动方法

解锁 Ubuntu 桌面后，桌面有两个入口：**智慧社区-查看场景**、**智慧社区-里程计巡检**。如果桌面提示启动器未受信任，可使用下面的终端命令。

只查看场景，在 Ubuntu 终端执行：

```bash
bash ~/sq_community_ws_20261008/start_scene.sh
```

查看当前 4.2 米场景并运行固定路线巡检：

```bash
bash ~/sq_community_ws_20261008/start_patrol.sh
```

等待 Gazebo 和机器人加载。运行终端按 `Ctrl+C` 停止该次启动。一次只启动一个入口；不要同时打开场景与巡检两套仿真。

本次巡检快捷脚本默认关闭外部 OCR 和语音；这样可以先测试已有场景与路线。识别服务、中文语音环境配置好以后，再显式打开，不代表原工程已经具备所有识别能力。


然后可查看：

```bash

source devel/setup.bash
```

本次未改写 `~/.bashrc` 的默认工作空间，避免你的其他工程受到环境覆盖。

## 建图和导航入口

先停止其他仿真，再启动建图：

```bash
bash ~/sq_community_ws_20261008/start_mapping.sh
```

另开终端并加载上述环境后，保存真实建图结果，建议使用新文件名保留随包地图：

```bash
rosrun map_server map_saver -f ~/sq_community_ws_20261008/src/sq_community/maps/my_slam_4p2
```

停止建图后，再用这张地图启动 move_base 路线：

```bash
bash ~/sq_community_ws_20261008/start_navigation.sh \
  map_file:=$HOME/sq_community_ws_20261008/src/sq_community/maps/my_slam_4p2.yaml \
  enable_ocr:=false enable_voice:=false
```

当前导航脚本如果没有指定 `map_file`，会使用随包几何先验图；它不能作为已完成 SLAM 建图的证据。不要同时运行里程计巡检和 move_base 巡检，也不要将旧场景地图用于新场景。

## OCR 下一步怎么接

当前 ZIP 包含 OCR 源码，但没有可直接使用的 EasyOCR 服务环境与下载后的模型权重。需要在独立 Python 3 环境安装依赖、准备权重、启动 `tools/plate_ocr_server_4p2.py`。

若服务运行在 Windows 宿主机，应确认 VMware NAT 适配器地址、8765 端口和虚拟机到服务的 `/health` 请求。原默认地址 `192.168.232.1` 不适用于本次虚拟机网段，不能照抄。

服务可用后，按实际地址执行，例如：

```bash
bash ~/sq_community_ws_20261008/start_patrol.sh \
  enable_ocr:=true ocr_url:=http://<实际服务地址>:8765/ocr
```

### 2026-10-08 图形窗口崩溃修复

重启虚拟机后，用户启动场景时出现 `VMware: vmw_ioctl_command error Invalid argument`、`Aborted (core dumped)`，`gazebo_gui` 退出码 134；场景后台 `gzserver` 仍在运行。原先的首次启动检查没有覆盖这次重启后的图形驱动行为。

已在四个 `start_*.sh` 启动脚本中加载工作空间的 `software_render_env.sh`，设置 `LIBGL_ALWAYS_SOFTWARE=true` 和 `GALLIUM_DRIVER=llvmpipe`，通过软件渲染绕过虚拟 GPU 路径，并关闭旧 Gazebo 模型数据库自动查询。设置依据见 [Mesa 环境变量官方说明](https://docs.mesa3d.org/envvars.html)。启动脚本修复前的备份保存在 `acceptance/gui_fix_20261008_backup/`。

本次已将软件渲染 `gzclient` 接入用户正在运行的后台，实际看到了场景与纹理，图形窗口恢复。后续仍使用相同的启动命令和桌面入口，无需手工加环境变量。软件渲染可能降低帧率，完整路线测试应同时记录仿真的实时速度。

恢复的独立图形窗口可直接关闭；停止整个场景仍在原启动终端按 `Ctrl+C`。若将来要恢复硬件渲染，请先检查 VMware 图形驱动兼容性，再使用备份，不要把窗口出现等同于兼容性已解决。
