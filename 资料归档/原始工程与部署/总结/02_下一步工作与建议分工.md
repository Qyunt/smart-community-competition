# 下一步应该做什么

本计划依据实际源码、独立静态检查以及本机保存的《第八届全球校园人工智能算法精英大赛算法应用赛道-智慧社区规则.pdf》。后续如组委会另有修订，应以团队收到的正式通知为准。

## 先抓住复赛重点

规则列出：场景搭建 15 分，建图/导航/避障 20 分，视觉识别 15 分；技术方案与答辩材料另占 50 分。当前项目已有场景和巡检骨架，下一阶段最有价值的是证明真实建图导航能够运行、接通核心识别，并同步准备材料。

复赛视频需要同时展示 Gazebo 和 RViz，并包含完整建图、移动识别以及核心代码讲解。规则建议总时长 8～12 分钟、视频小于 300 MB，源码 ZIP 小于 150 MB。总决赛每场 5 分钟，与复赛视频时长属于不同要求。

## 第一阶段：确认场景和机器人，避免后面反复重做

拿规则图逐区核对 A/B 街、人群区、楼宇、道路、停车区、斑马线、红绿灯、指示牌和行驶方向，形成“规则图—manifest—world”差异表。没有尺寸依据的坐标标记为比例估计或待确认，不能伪装成官方精确坐标。

与队友确认机器人最终尺寸：继续使用实验平台尺寸，还是将仿真模型改为交接记录中的 400×400 毫米。确定后同步修改 URDF、导航足迹、膨胀参数、地图净空检查和目标点，不要只扩大外观。重新生成或核验地图，并检查转弯、停止线和停车区域。

交付标准：一份团队确认的场景差异表和机器人尺寸表；当前截图；修改后静态检查通过。几何通过以后仍须检查相机遮挡。

## 第二阶段：把 SLAM、定位和导航单独验收

按顺序完成：

1. 单独启动建图入口 `sq_mapping_run_4p2.launch`，让 LiDAR 实际产生 GMapping 地图；保留 ROS 日志和建图录屏。
2. 用 map_saver 保存原始地图，记录分辨率、原点、生成时间与原始图；若做道路掩膜、补墙或裁剪，另存后处理版本并说明过程。
3. 停止建图后启动 AMCL/move_base，通过 RViz 核对 `/map`、`/scan`、`map→odom→base_link` 和初始位姿。
4. 先测一个目标，再测转弯和信号灯路段，最后用 `sq_autonomous_nav_4p2.launch` 测完整 33 点路线。
5. 保存每个目标的状态、耗时、终点误差、卡住/恢复情况、碰撞/压线记录和任务照片。连续跑 3 次，检查是否可重复。

`sq_autonomous_4p2.launch` 使用的里程计巡检可以做基线，但它不能替代 move_base 整圈验收。两个巡检控制节点不要同时运行。建图时不要同时运行 AMCL/map_server。

交付标准：实际 SLAM 原始地图、完整导航报告、Gazebo＋RViz 录屏、失败点说明。建议内部目标为 33/33 点完成且无碰撞，连续 3 次通过；这是团队验收建议，不是额外的官方评分条款。

## 第三阶段：先完成复赛核心视觉，再扩展其他任务

优先完成红绿灯、人偶和车牌三个核心能力。

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| 高 | 红绿灯相机识别及停止线响应 | 不读仿真真值；红/黄停车，绿灯按规则通过；保存相机判断和停止记录 |
| 高 | 部署 Python 3 OCR 服务，修正地址 | 虚拟机到服务的健康检查通过；CAR_1～CAR_3 真实图像进入识别并返回结果 |
| 高 | 人偶检测、A/B 街计数、外来人员定位 | 检测框和标签存图，输出各区与总人数，跨帧去重；不要直接输出场景清单里的示例数 |
| 中 | A/B/C 楼火灾识别 | 输出楼宇和隐患数量，保留检测图与低置信度处理 |
| 中 | 指示牌识别与路线决策 | 识别结果真正改变路线或运动行为，不能只播报 |
| 后续 | 电动车、垃圾桶、仪表、温度、泊车 | 每项分别实现算法、结果格式、输出/播报和验收图 |

车牌需测试未知号码、距离、角度和光照变化；旧三张已知图片通过只能视为集成测试。人群应补合适的观察视角，当前 14 个建议相机姿态尚未接入自主巡检。

建议把 OCR/YOLO 放在独立 Python 3 环境，以巡检事件触发图像处理，再把 JSON 结果发回 ROS。固定任务编号与结果结构，并为超时、低置信度和失败重试制定规则。不要为了装视觉库而直接破坏 ROS Melodic 的 Python 2 环境。

## 第四阶段：形成完整演示流程

把“启动—定位—导航—任务抓图—识别—输出/语音—返回停车”串起来。对未实现任务清楚记录为未实现或待复核，避免把“到达观察位”展示成“识别完成”。

补齐语音后端和中文输出；最终结果写入稳定的结果目录，保存日志、JSON 和带检测框的照片。现在程序默认写 `/tmp`，适合临时测试，正式录制前应复制到持久目录。

做好一键启动、超时停车和故障说明。单独测试模型缺失、相机无图、OCR 服务断开、导航超时等情况，确保出现问题后有明确输出。

## 第五阶段：材料与代码同步推进

准备四项复赛交付物：技术方案 PDF、源代码 ZIP、答辩展示 PDF、综合演示与答辩 MP4。队名占位符需要替换。

技术方案应讲清 ROS 节点和通信、SLAM 与导航选型、检测训练和 OCR 机制、硬件传感器选型、仿真到实车的部署方法，以及光照、反光、传感器噪声等影响。每个“完成”结论附对应运行证据和指标。

录制前安排一轮完整彩排，再录建图、定位导航、视觉输出和核心代码讲解；文档不能把尚未验收的功能写成已完成。视频大小与画面清晰度应同时检查。

## 建议团队分工

| 角色 | 负责内容 | 交付给队友的结果 |
|---|---|---|
| 仿真与导航 | 场景规则核对、机器人尺寸、地图、TF、GMapping、AMCL、move_base | 冻结场景、地图、33 点导航报告 |
| 视觉与播报 | OCR、人偶、火灾、后续识别、Python 3 服务、结果输出 | 模型/环境说明、接口、检测图和指标 |
| 集成与材料 | 一键启动、日志归档、技术方案、答辩稿、演示录制 | 完整可复现运行包和提交材料 |

若只有两个人，前两项各一人负责，集成和材料共同完成。用版本控制记录修改，每次地图或模型变化都标注版本，避免同一天使用不同地图坐标。

## 今天最值得完成的三件事

1. 用本机启动脚本熟悉当前场景，记录传感器话题和第一段巡检情况。
2. 与组员确认道路/人群区疑问和机器人最终尺寸，形成一页差异表。
3. 导航负责人开始一次真实建图验收，视觉负责人准备人偶检测并接通 OCR；同时建立材料提纲。

本次安装验收的实际通过范围见 `03_部署与启动说明.md`，不能用静态自检或组员旧记录替代本机完整任务结果。
